EduGear — what is left before launch

For Ahmad and Adewale · 28 November 2026

The system is built, deployed and working. The live service at api.edugear.ng is healthy, running the latest code, with its database and cache connected. The staging copy is the same. Everything that can be checked automatically passes.

What is left is one thing that stops schools using it, two security jobs for today, and some paperwork that stops you signing a contract but does not stop the product running.

1Email does not sendAhmadBLOCKS LAUNCH

In plain terms: right now EduGear sends no email at all. No staff invitations, no password resets, and no parent can be invited to the portal. A school would see "invited" on screen and the person would simply never receive anything.

It fails quietly, which is the dangerous part. Nothing shows an error. Because inviting a parent now requires the inviting staff member to have confirmed their own email first, a broken email system shows up as a confusing "you don't have permission" message instead of "email is broken".

Why it broke

The Resend account was moved from A4's account to the one under edugearsupport@gmail.com. The settings currently published on the edugear.ng domain were issued by the old account, so the new account does not recognise the domain and refuses to send.

What to do

  1. Sign in to Resend as edugearsupport@gmail.com, go to Domains, and add edugear.ng.
  2. Resend will show you a set of DNS records to add. One of them, called resend._domainkey, will be different from the one already there.
  3. In the DNS settings for edugear.ng, replace the old resend._domainkey record with the new one. Do not add a second one next to it — two of these on the same name cancel each other out and email stays broken.
  4. If edugear.ng is still listed on the old A4 Resend account, remove it there first.
  5. Back in Resend, click Verify DNS Records. It usually passes within minutes.
  6. Create a new API key on this account, and put it in Railway → production → Variables as RESEND_API_KEY. A key from the old account will not work even after the domain verifies.
  7. Redeploy.

How to know it worked

curl -s -X POST https://api.edugear.ng/api/auth/register-school \
  -H 'Content-Type: application/json' \
  -d '{
    "schoolName":"Email Test School",
    "schoolEmail":"edugearsupport+testschool@gmail.com",
    "firstName":"Test","lastName":"Owner",
    "email":"edugearsupport+testowner@gmail.com",
    "password":"Kalabari-Mangrove-77!",
    "phone":"08031234567"
  }'

A 201 response means the school was created. Then check the edugearsupport@gmail.com inbox — anything with a + in it lands in the same place — for a message with a "verify your email" link. Check the spam folder: a newly set up sending domain often lands there on the very first message.

If no email arrives: open the Emails tab in Resend. If your test is listed there, the email left EduGear and the problem is delivery. If nothing is listed, EduGear never reached Resend — which means the API key is still the old one.

Afterwards

Sign in to the admin console as edugearsupport@gmail.com, find "Email Test School", and purge it. Cancelling only marks it cancelled; purging removes it properly, and asks you to type the school name to confirm because it cannot be undone.

2Two security jobsAhmadTODAY

Change the database password

The production database password was shown on screen several times while fixing a connection problem, so it should be treated as known. That database can be reached from the public internet.

  • Neon → your project → Roles → reset the password for neondb_owner
  • Update both DATABASE_URL and DIRECT_URL in Railway → production
  • Redeploy, then run the check at the bottom of this page

When pasting the new string into Railway, delete &channel_binding=require from the end of it. Neon includes it by default and EduGear cannot use it. Production works today precisely because it is not there.

Change the admin console password

The first one was generated during setup and has been handled a few times. Changing it signs out every other session immediately.

3Company registrationAdewaleBEFORE SIGNING

The three legal documents have two blanks left, appearing in six places: the RC number and the registered office address. Both come from CAC registration, which has not been done.

This does not stop the product working. A school can use EduGear today. What it stops is signing a data processing agreement, because without registration there is no company to name as the party signing it — and a school's lawyer will ask for the RC number.

It also affects registering with the Nigeria Data Protection Commission, which identifies a business by its registration.

Three ways forward — pick one

OptionWhat it means
Register with CAC Cleanest. Fill the six fields and the documents are finished.
Sign as the business as it exists today A business name registration, or the owner personally. The documents then say what is actually true.
Hold the documents Start pilot schools on a simpler written agreement, and finish these once CAC is done.

Do not put in a placeholder RC number. These documents were deliberately written so that every statement in them can be proved. The registration number is the first thing a lawyer checks, and an invented one undoes the credibility of everything else.

4InsuranceAdewaleBEFORE SIGNING

The processing agreement commits A4 to having cyber and data-protection insurance before handling any school's data. Nigerian data protection rules make an insurance clause compulsory, so it cannot simply be removed from the document.

As written it is a promise with a deadline attached, which is honest — but it becomes binding the moment a school signs. Either the cover needs to exist, or the school needs to be told it does not.

6How to check everything is still fine

npm run verify:deploy -- https://api.edugear.ng production https://www.edugear.ng

Eleven checks, takes seconds, changes nothing and needs no password. It asks the live service what it actually believes rather than reading a settings page back at you. Run it after any change to Railway settings.

7Things that will waste a day if nobody warns you

SymptomWhat it usually means
"Can't reach database server" Almost anything. During setup this one message stood for a typing mistake, a wrong password, and a broken network setting. Test the connection with psql first — it reports the real reason.
A command hangs about five seconds, then says the database is unreachable The computer's IPv6 networking is advertised but does not work. Other tools quietly fall back; EduGear's database layer does not.
An npm run command ignores your options Put -- before them: npm run thing -- --option.
A Railway setting seems to have disappeared Settings do not carry between staging and production. Each is set up separately. See docs/railway-service-settings.md.
